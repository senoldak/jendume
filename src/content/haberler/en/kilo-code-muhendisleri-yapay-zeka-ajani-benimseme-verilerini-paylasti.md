While industry discussions often focus on model benchmarks and capability scores, real-world usage data reveals a different story about how software developers adopt artificial intelligence tools. Brendan O'Leary, a developer relations engineer at Kilo Code, examined extensive token usage data to understand actual adoption patterns. The dataset is derived from real-world infrastructure usage across open-source command line interfaces, editor extensions, and cloud agent environments.

Contrary to the common industry narrative that prioritizes benchmark rankings, developers do not always choose the highest-scoring models. Instead, AI adoption depends heavily on establishing trust. The journey resembles a four-rung ladder, starting from basic auto-complete features and moving toward chat interfaces and orchestrated multi-agent workflows. Teams frequently build dependencies on tools that match their specific use cases regardless of raw capability scores.

The analysis highlights that AI adoption can break down at specific technical junctions, including context construction, model routing, and feedback loops. Factors such as file inclusion, codebase indexing, semantic reasoning, and caching performance heavily influence developer experience. Addressing these friction points is seen as essential for scaling agentic workflows successfully.

Coding assistants and agentic engineering remain among the most prevalent use cases for token consumption across the industry. Senior engineers with deep systems thinking are often found to extract the most value by providing precise context. The findings suggest that the future of AI tooling depends less on raw model capability and more on reliability and user trust.
